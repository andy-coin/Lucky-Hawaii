## Phase Goal

**As a** 作詞人 Andy, **I want to** 用一個指令把多個授權相容的台灣詞庫自動清洗成同一格式的「詞庫包」，並在網站偏好設定裡切換比較, **so that** 查到的詞更符合台灣日常語感，簡體、中國用語與冷僻詞大幅減少.

<objective>
Build the gray-area AI step completely — verdict cache, estimate gate, hard caps, resume, provider adapters (recorded, direct Gemini, Worker) and pack rebuild — tested offline, so that Andy's later one command (`GEMINI_API_KEY=… npm run lexicon:judge`) judges the ≈ 34 k single-source words within the free quota and republishes the packs with new versions.

Purpose: LEX-04 (gray judged by free AI within free tokens) and LEX-03 (the comprehensibility standard in the prompt). The real run cannot happen in the cloud (no key, Worker not deployed): packs stay built with unjudged gray words kept (C4, OD-6).
Output: lex/judge.py, rules.resolve, judgments.tsv, `build.py judge`, `npm run lexicon:judge`, offline tests incl. local fake HTTP servers, README AI section.

Planner decision recorded for Andy (06-08 writes it to TEST-CHECKLIST): the pre-run gate refuses only when the estimated tokens exceed --max-tokens; when there are more batches than --max-requests the run proceeds and stops at the cap so a low daily free quota just means "run again tomorrow" (C3 estimate + hard cap, RESEARCH Pitfall 8).

This plan implements: C3, C4 (Worker adapter optional, direct Gemini default — OD-10), C5 groundwork (RecordedProvider + recorded fixture), D2 (allowlist beats D), LEX-06 (content hash bumps versions after judging). API surface decisions: .planning/phases/06-lexicon-packs/COVERAGE.md. Decision IDs: see 06-01-PLAN.md objective.
</objective>
