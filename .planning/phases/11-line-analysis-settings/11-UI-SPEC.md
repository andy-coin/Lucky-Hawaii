# Phase 11 — UI Design Contract（句構分析與設定頁）

> Visual and interaction contract for Phase 11. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Andy is asleep and pre-authorized "decide grey areas yourself". 11-CONTEXT.md locks A–E. Every choice below that CONTEXT did not lock is tagged **(Claude's discretion)** and listed in section 1 as a **D-xx** so Andy can veto it by editing this file. Three places differ from a CONTEXT or Phase 10 *mechanism* (not its intent) and are marked **Overrides** in section 1: D-05 (the guessed structure cannot be a "lighter colour"; it is marked by 「≈」 plus a slanted face, because a lighter tone fails 4.5:1, measured), D-07 (Phase 10 D-15 hid the selection bar above 20 characters; the bar now stays for any selection that touches a countable line, but then offers only 「📏 分析」), D-14 (the 「濃」 band strength is opt-in and can drop below 4.5:1 for 5 of the 16 default colours in the dark theme; disclosed, with an in-page advisory).
> This phase **adds** per-line markers to the Phase 10 mirror layer (a right-hand gutter or a tail-attached label), one 「📏 分析」 button and one analysis panel next to the Phase 10 selection bar, a 「逐行標記」 switch and a 「更多設定…」 button to the 「韻腳 ▾」 menu, and one expandable section 「韻腳地圖與句構分析」 inside ⚙️ 偏好設定. It is not a redesign: the Phase 9 section module, the Phase 10 coloring rules and the Phase 8 shell stay as they are.
> Reuses Phase 5 (rem, `--hit` 44px, `--sp-*`, breakpoints S ≤ 440 / M 441–900 / L ≥ 901, z-index scale, light / dark / custom themes, `html.kb-open`), Phase 7 (`--action-*`, specific verb + object labels), Phase 8 (`<details class="settings-backups">` pattern, two-tap `data-armed` confirm, `.word-ctx-menu` shell, `lhPlaceMenu`, 4 sizes / 2 weights), Phase 9 (`.section-menu*`, `.type-grid` / `.type-row` radios, `.section-color-input`, native colour input "preview on `input`, commit on `change`", `#lhLive`) and Phase 10 (`.rm-switch` rows, `--rm-cN` palette variables, the mirror layer and `_lhMapSync`, `#rhymeSelBar`, `lhMapCloseAll`, `lh:map`, 22 autonomous decisions D-01…D-23).
> All UI text is Traditional Chinese (台灣繁體). Simplified Chinese is forbidden.

## 1. Decisions Log

| ID | Decision | Rationale |
|----|----------|-----------|
| D-01 | **Marker = one `span.lm-mk` per analysable line, inside the Phase 10 mirror, absolutely positioned.** The span is appended after the line's last character (before the `\n`), `position: absolute; white-space: nowrap; pointer-events: none`, with **no** `left` / `top` set in tail mode (so the browser uses the static position: right after the last character, on the **last visual row** of a wrapped line) and `top: auto; left: auto; right: …` in gutter mode (vertical static position kept, horizontal pinned into the gutter). Because an absolutely positioned box takes no inline space, it can never move a wrap point (E1). The mirror shows a marker even when the line has no colour band (`rm-on` is set when any band **or** any marker exists). Children are built with `createElement` + `textContent`. The marker text colour is set on the marker itself (`color: var(--text-secondary)`) because the mirror text is `transparent`. Blank and punctuation-only lines (CONTEXT A3) get no marker. Sections beyond the Phase 10 size cap (`LH_WD_BIG` chars or 5000 lines) get no markers. (Claude's discretion) | Static-position trick keeps the textarea and the mirror untouched, so Phase 10's wrap-identity invariant is preserved by construction. A held-out test sweeps widths ±1px around a wrap boundary to prove "last visual row" (section 9.1). If a browser places the marker on the wrong row at an exact boundary, the fallback is a zero-width `inline-block` wrapper carrying the same span; the visible contract does not change. |
| D-02 | **Gutter mode (默認 「靠右欄」) geometry (CONTEXT C2).** A section whose markers are on and whose position is 「靠右欄」 gets class `lm-gut` on `.lyrics-section` and two custom properties set from JS: `--lm-fs` (marker font size: `0.75rem` / `0.875rem` / `1rem` for 小 / 中 / 大) and `--lm-w` (gutter width in px = **min(sum of the enabled token widths × `--lm-fs`, 36% of the textarea `clientWidth`)** + `var(--sp-2)` gap; token widths in section 3.2). The textarea **and** the mirror get `padding-right: calc(0.75rem + var(--lm-w))` from one shared CSS rule (the existing `.section-textarea, .rhyme-mirror` block), and `_lhMapSync` keeps adding the scrollbar width to the mirror as in Phase 10. The marker's `right` is `calc(var(--lm-bar, 0px) + 0.75rem)` and its `width` is `var(--lm-w)` minus the gap, so the column sits between the text and the right padding, left of the scrollbar. `_lhMapSync` also copies `--lm-lh` (the textarea's computed `line-height` in px) and `--lm-bar` (scrollbar width in px) onto the mirror; the marker uses `line-height: var(--lm-lh)` and `height: var(--lm-lh)` so its text is vertically centred on the lyric line at every size. Overflow of the structure text inside the column is clipped with an ellipsis. The cap uses `clientWidth` (padding box), so changing the padding cannot re-trigger the `ResizeObserver`. (Claude's discretion) | CONTEXT C2: textarea and mirror receive identical right padding, so characters wrap identically; the 36% cap keeps at least about 64% of the width for writing on a 390px phone (section 8). |
| D-03 | **Tail mode (「句尾後」).** Section class `lm-tail`; no padding change. The marker has `margin-inline-start: 0.5em` and the tokens are separated by a middle dot (`.lm-t + .lm-t::before { content: "· " }`, tail mode only). The marker is clipped by the mirror's edge when the line is nearly full (documented in the setting's helper line, section 7). (Claude's discretion; position is a CONTEXT C2 choice, the dot separators and the 0.5em offset are mine) | The dot keeps `A · 7 · 3+4` from CONTEXT; gutter mode replaces dots with fixed-width columns so numbers line up (D-04). |
| D-04 | **Token order and format (CONTEXT C1, B3).** `[韻腳字母] [字數] [對照差異] [斷句結構]`, each token is a `span.lm-t` (classes `lm-t-r`, `lm-t-c`, `lm-t-d`, `lm-t-s`). Letter: `A`…`Z`, `a`…`z`, `*`, or `-` (no rhyme), underlined in the family colour exactly like the Phase 10 header strip (`border-bottom: 0.125rem solid color-mix(in srgb, var(--text-primary) 30%, var(--rm-c))`, none for `-`), same letters as the strip, following 寬韻 / 嚴格. Count: digits only (「7」). Diff: appended to the count slot, written as 「≠8」 (no space after ≠) only when the same-numbered line of the comparison section has a different count; absent when equal or when the other section has no such line; if 字數 is off but 對照差異 is on, the diff token stands alone. Structure: 「3+4」 when the line's break points are all explicit (spaces / punctuation), 「≈2+2+3」 when at least one fragment was guessed (the whole string gets the 「≈」 prefix, CONTEXT A2); a line with only one group (no break, or a fragment of 4 characters or fewer with no break) shows **no structure token** (the count already says it). In gutter mode the tokens sit in fixed-width columns (right-aligned digits, left-aligned text); in tail mode they are inline with 0.5em gaps. The diff token is `--text-primary` at weight 700 (the only emphasised token, so only differences pop). All other marker text is `--text-secondary` at weight 400. Example: `A 7 3+4` (letter, count, structure on); `7 ≠8 ≈2+2+3`. (Claude's discretion) | Hierarchy from tokens, not colours; the letters tie into the existing family-colour system. |
| D-05 | **Guessed structure is marked by 「≈」 and a slanted face, not by a lighter colour. Overrides** CONTEXT A2 「較淡的字」 in mechanism only: `--text-secondary` on `--card-bg` measures **5.62** (light) / **5.32** (dark); mixing it 15% toward the card already gives **4.07** / **4.30** (< 4.5), 25% gives **3.33** / **3.70**. So the guessed string keeps `--text-secondary` and gets `font-style: italic` (a synthetic slant, Noto Sans TC has no italic) in addition to the 「≈」 prefix; the glyph is the non-colour carrier, the slant is reinforcement. (Claude's discretion) | AA first, meaning stays instantly readable: 「≈」 always means "the machine guessed". |
| D-06 | **Typing and staleness (E2).** Markers follow Phase 10 D-06: any edit that changes the line count or happens mid-line sets `rm-stale` (whole mirror hidden). For an ordinary edit at a line end: **tail mode** hides only the markers by toggling one more class `lm-typing` on the mirror root (`.lm-typing .lm-mk { visibility: hidden }`), removed by the repaint, so a newly typed character never overlaps a stale label; **gutter mode** leaves the markers visible with possibly stale values for at most about 1 s (200 ms debounce, 1000 ms max wait), because the gutter never collides with the text. `lm-typing` is a class toggle on a sibling `div`, the only mirror write allowed during composition besides `rm-stale`; zero children are touched. (Claude's discretion; extends Phase 10 D-06) | Static labels in the gutter are harmless when stale; a label at the end of the line is not. |
| D-07 | **Selection bar gets a third action and a wider trigger. Overrides** Phase 10 D-15 「at most 20 characters, at least one Chinese character」. The bar now appears whenever the selection touches at least one analysable line (a line with `lhCountWords` > 0), at any length up to the whole section. Rules: **≤ 20 characters and ≥ 1 Chinese character** → `[🔍 查韻：{字}] [✨ AI 建議] [📏 分析]` plus `[指定讀音]` when Phase 10 D-08 allows it; **otherwise** (long selection, or no Chinese character such as English or kana lyrics) → `[📏 分析]` only. Order is fixed: the lookup actions first, 「分析」 after them, 「指定讀音」 last (so the first button stays the Phase 10 focal point). Debounce, placement (below the last selected line, docked at the bottom of the visible viewport when it does not fit), dismissal, Alt+ArrowDown path, no-focus-steal on `pointerdown` / `mousedown`, composition and drag exclusions are all **unchanged** from Phase 10. The bar wraps to two rows at 390px (four buttons about 380px). (Claude's discretion) | CONTEXT B4: "要看整段就把整段反白後按分析" needs the bar to exist for a whole-section selection; the lookup buttons make no sense there. |
| D-08 | **Analysis panel `#rhymeAnalysis`.** A non-modal `.word-ctx-menu.section-menu` (`role="dialog" aria-label="句構分析"`), width `min(24rem, calc(100vw - 1rem))`, `max-height: calc(var(--app-h) - 1rem)`, z 10000. It opens when 「📏 分析」 is activated (button gets `aria-expanded` / `aria-controls="rhymeAnalysis"`; pressing it again closes) or by the hover rule (D-10). **Placement:** directly below the bar (`bar.bottom + 4px`, `left` = bar `left`), through `lhPlaceMenu`; if it does not fit below, **above** the bar; if neither side fits (844×390 landscape with keyboard), it takes the larger side and scrolls internally (minimum visible height `8rem`). It does not move the bar. **Override of CONTEXT C5 ("同時只開一個浮層"):** the panel is attached to the selection bar and the two count as one floating layer; every other floating layer is still closed. Opening it closes the stats popover, the 韻腳 menu, the export menu and the 指定讀音 row (the bar stays); closing the bar closes the panel. Dismiss: Esc (focus and selection go back to the textarea exactly like the bar, Phase 10), 「關閉句構」, pointerdown outside both the bar and the panel, the selection changing or collapsing, scrolling the lyrics area, starting a composition, song switch, panel collapse, `storage` event. Pointerdown on the panel's non-scrolling surface is default-prevented so the selection survives; the scroll region keeps native touch scrolling. Content: section 4. Rows are plain text (not focusable); the panel's own controls are only the scroll region (`tabindex="0"`, `role="region" aria-label="逐行句構"`, only when it overflows) and the close button. Keyboard open (`e.detail === 0`) focuses the panel container (`tabindex="-1"`); pointer / touch open focuses nothing. (Claude's discretion) | A separate dialog (not a taller toolbar) gives the table its own accessible role and lets it reuse `lhPlaceMenu`. |
| D-09 | **Comparison semantics (CONTEXT B1, B3, B4).** Comparison section = the nearest earlier section of the **same type** (Phase 9 `type`; for `custom`, the same name). The first section of a type has none. The marker diff compares **character count only** (CONTEXT B3). The panel shows, for each selected line, the comparison line's count and structure side by side and a verdict glyph: 「✓」 (`aria-label` 字數相同) when counts are equal, 「≠」 (`aria-label` 字數不同) when they differ; structure differences are shown but never change the verdict (the writer compares 3+4 against 4+3 by eye). A missing comparison line shows 「對照段落沒有第 {i} 行」 and no glyph. Line numbers are "n-th non-empty analysable line" (CONTEXT A3) on both sides. (Claude's discretion) | Keeps one definition of "different" across marker and panel. |
| D-10 | **Hover auto-open (CONTEXT C4), default off.** Only for `(hover: hover) and (pointer: fine)` (checked in JS with `matchMedia` at the moment of the selection). Arming: the selection bar has just appeared from a mouse selection. Hover zone = the textarea's own box, vertically limited to the span from the top of the first selected visual row to the bottom of the last one (measured once with the Phase 10 `lhCaretRect` when the bar is placed; no extra layout reads afterwards). If the pointer rests in the zone with no `pointermove` of 3px or more for **1.5 s**, the panel opens exactly as if 「分析」 had been pressed, without taking focus. The timer is cancelled by: pointer movement ≥ 3px, wheel / scroll, `keydown`, selection change, composition, the bar or panel being dismissed, any open menu. Moving out of the zone after the panel is open does **not** close it (no flicker). Touch devices never arm it; the setting row is still shown on every device with the caption 「只有接了滑鼠的電腦會自動出現；觸控請按「分析」」. (Claude's discretion) | CONTEXT C4 does not say how to know "over the selection"; the line-span zone avoids per-character hit testing in a textarea. |
