# Phase 9 — UI Design Contract（段落模組）

> Visual and interaction contract for Phase 9. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Andy is asleep and pre-authorized "decide grey areas yourself". 09-CONTEXT.md locks A–G. Every choice below that CONTEXT did not lock is tagged **(Claude's discretion)** and is listed in section 1 as a **D-xx**, so Andy can veto it by editing this file. One place (D-10, the mechanism behind the grey undo buttons) deliberately differs from a CONTEXT sentence; it is marked **Overrides** in section 1. D-11 is a documented cost, not an override.
> This phase **upgrades the Phase 8 section block** (`.lyrics-section`) into a module and adds two drag systems, one popover, a history, and counts. It is not a redesign of the lyrics panel: the Phase 8 header (`.lyrics-head`, song list, export), the 情境 & 標籤 block, hashtag chips, and the lyrics textarea look stay as they are.
> Reuses Phase 5 (rem, `--hit` 44px, `--sp-*`, breakpoints S ≤ 440 / M 441–900 / L ≥ 901, z-index scale, light / dark / custom themes, `html.kb-open`, input floor `max(16px,1rem)`), Phase 7 (`--action-*`, specific verb + object labels, no generic 「取消」/「確定」, AA decided up front) and Phase 8 (`--danger-*`, `.word-ctx-menu` popover shell, `lhPlaceMenu`, `.copy-toast`, outline header buttons, accent stripe for "active", 4 sizes / 2 weights, no new hex literal in layout rules).
> All UI text is Traditional Chinese (台灣繁體). Simplified Chinese is forbidden. Section type names stay English (CONTEXT B1).

## 2. Section Module (EDIT-02, EDIT-05, EDIT-07)

### 2.1 DOM shape (existing class names and `data-index` / `data-id` kept; IDs `#lyricsSections`, `#leftPanel` unchanged)

```
#lyricsSections
  .lyrics-section[data-id][data-index][data-type][style="--sec-color:#rrggbb"?][data-h?]
     ::before                              ← 0.25rem color bar, only when a color is set
     .lyrics-section-header
        button.section-handle              「⋮⋮」 touch-action:none, cursor:grab
        span.section-chevron               「▾」 (unchanged)
        button.section-type                type name; click = cycle, contextmenu/long-press = menu
        span.section-count                 「{N} 字」
        button.section-remove              「−」 (hidden when the song has 1 section)
     .section-body > textarea.section-textarea   (unchanged)
     .section-resize[role="separator"]     bottom bar; display:none while .collapsed
.section-drop-line                         ← one element, created on drag, removed on end
.section-drag-ghost                        ← fixed, created on drag, removed on end
#sectionMenu.word-ctx-menu.section-menu    ← one element, built once, refilled with textContent
#lhLive                                    ← visually hidden aria-live="polite" region (announcements)
```

`data-type` holds the type key (`intro|verse|prechorus|chorus|inter|bridge|outro|custom`) so tests and CSS can read it. The inline `style` only ever receives `--sec-color` with a value that already passed `^#[0-9a-f]{6}$` (A4); `--sec-h` the same way with a finite number in range. No `innerHTML`, no `setAttribute('on…')` strings (the Phase 8 inline handlers `onSectionHeaderClick` etc. are replaced by delegated listeners on `#lyricsSections`).

### 2.3 Type cycle, numbering, naming (visible contract)

| Rule | Result |
|------|--------|
| Cycle (click / Enter / Space) | Intro → Verse → Pre-Chorus → Chorus → Inter → Bridge → Outro → Custom → Intro (B1) |
| Numbering | A type that appears 2 or more times gets Roman numerals in current order: `Verse I`, `Verse II`, … `Verse X`, `Verse XI`…. A type that appears once shows only its name (`Chorus`). Custom is never numbered. Recomputed immediately after reorder, add, delete, type change (B2) |
| Roman numerals | Standard subtractive (IV, IX, XL…); no cap needed for realistic song length |
| Custom display | `custom` string trimmed; empty → the word `Custom`. A non-empty name is shown as typed (max 40 characters). The string is kept when the type is cycled away and back |
| Label button text | The computed display name only (no icon, no chevron). Width follows the text; `max-width` per D-01 |
| New section type (＋) | Next common type after the previous section: Verse → Pre-Chorus → Chorus → Verse …; unknown or first section → Verse (B6) |
| `label` model field | Always rewritten to the displayed name after any structural change (A3). Not shown anywhere that the button does not already show |
| Accessible name | `aria-label` 「{名稱}，段落類型，按一下切換」 — begins with the visible text (label-in-name). `aria-describedby="secTypeHint"` points to one visually hidden node: 「按 Enter 切換類型；按 Shift+F10 開啟段落設定」 |

### 2.4 Word count (E1, E2)

Rule shown to the user as 「N 字」: each Chinese character (incl. full-width) = 1; a run of letters / digits = 1 word; spaces and punctuation = 0. Section count and `#songTotal` (「共 N 字」) update on `input` and on `compositionend`, never during composition, never by touching the textarea. The song total is the sum of the section counts. Both are plain text (`textContent`) and not live regions.

| State | Visual |
|-------|--------|
| Default | Header (`--container-bg`), textarea (`--card-bg`), 1px `--border`, radius `0.625rem` |
| Colored | Default + `0.25rem` left bar + tinted label button (D-03) |
| Collapsed | Header only; resize bar hidden |
| Dragging (source) | `opacity: 0.5`, `cursor: grabbing` on `body` |
| Drop target for a word | Textarea inset outline `2px --highlight-border` (D-08) |
| Auto-expanding (word dwell over collapsed header) | Header background `color-mix(in srgb, var(--highlight-border) 25%, var(--container-bg))` for the 600ms dwell (static, no progress animation) |
| Flash | `outline: 2px solid var(--highlight-border)` for 700ms (D-14) |
| Focus | Global `:focus-visible` ring on every control above |

## 4. Drag Reorder (EDIT-02)

| Phase | Behavior |
|-------|----------|
| Start | `pointerdown` on `.section-handle` (button 0 or touch). Movement ≥ 4px starts the drag (a tap on the handle does nothing). Pointer is captured on the handle so the gesture survives leaving the panel. Touch needs no long-press (`touch-action: none` on the handle only) |
| During | Source section `opacity: 0.5`; ghost (D-07) follows the pointer, horizontally clamped inside the panel; the drop line is placed above the section whose vertical midpoint is first below the pointer, or after the last section. `body.is-section-dragging`: `user-select: none; cursor: grabbing`. Collapsed sections count as one row each |
| Auto-scroll | When the pointer is within `3rem` of the top or bottom of the scroll parent of `#lyricsSections` (the nearest scrollable ancestor), scroll up or down at `0.25rem`–`0.75rem` per frame proportional to depth into the zone. This is functional, so it stays on under reduced motion |
| Commit | `pointerup` anywhere: model reordered, labels recomputed (A3), one undo step, save, re-render, flash the moved section (D-14), announce 「{名稱} 已移到第 {n} 段，共 {m} 段」 in `#lhLive` |
| Cancel | Esc, or `pointercancel`, or releasing at the original position: nothing changes, nothing is recorded |
| Keyboard | Focused handle: Alt+↑ / Alt+↓ move one place (one undo step each; focus stays on that section's handle after re-render); a move at the ends is ignored silently. The popover's 上移 / 下移 do the same (touch fallback) |
| Isolation | The header no longer has `draggable`, so text selection inside the label button, the count, and the textarea can never start a section drag. The Phase 8 `onSectionDrag*` handlers are deleted |

Ghost: `position: fixed; pointer-events: none; z-index: 10000; width: min(18rem, 80vw); opacity: 0.95`, header look (background `--container-bg`, 1px `--border`, radius `0.625rem`, `box-shadow: 0 4px 16px rgba(0,0,0,0.18)`), contents: color bar if any + type name (`0.875rem`/700) + count. Drop line: `position: absolute` inside `#lyricsSections` (needs `position: relative` on the area), `left: 0; right: 0`, `height: 0.25rem`, `background: var(--highlight-border)`, `z-index: 3`.

## 5. Resize Height (EDIT-02)

| Aspect | Spec |
|--------|------|
| Bar | `.section-resize`: full width, background `--container-bg`, `border-top: 1px solid var(--border)`, height per D-11. ## 8. Word Drag Insert (AI-06)

### 8.1 Sources and gesture

| Item | Spec |
|------|------|
| Sources | `.ai-word-card` and `.char-card` (F1). Not in report mode (`#aiWordsContainer.report-mode`): there the Phase 7 click behavior has priority and drag is off |
| Mouse | Button 0 held and moved > 5px starts the drag. Right button (Phase 7 context menu) never starts it. Plain click behavior (存進保留池 / 選取) is unchanged; the `click` right after a drag is swallowed once |
| Touch | Press and hold ~400ms without moving more than 10px starts the drag; haptic `navigator.vibrate(10)` if present; native `contextmenu` and text selection are blocked on the cards (`-webkit-touch-callout: none`). Movement > 10px before 400ms means "scroll", and no drag starts. Once started, `touchmove` is `preventDefault`-ed (non-passive) so the list does not scroll under the finger |
| Source card | `opacity: 0.5` until the drag ends |
| Ghost | `position: fixed; pointer-events: none; z-index: 10000`; pill with `background: var(--card-bg)`, `2px solid var(--highlight-border)`, radius `0.75rem`, padding `var(--sp-1) var(--sp-3)`, `1rem`/700 `--text-primary`, `box-shadow: 0 4px 16px rgba(0,0,0,0.18)`, text = the word (`textContent`, max `14rem` with ellipsis) |
| Drop target | Only `.section-textarea` under the pointer (found with `elementsFromPoint`, ghost excluded). Anything else (including the header) means "no target": ghost stays, no caret. Release with no target = cancel, nothing changes (F6) |
| Caret | Position measured with a hidden mirror `div` copying the textarea's font, padding, width, wrapping, `white-space: pre-wrap; overflow-wrap: anywhere`; the insertion index is the character nearest the pointer; the caret element is clamped inside the textarea box and follows its scroll offset. Updated at most once per animation frame |
| Edge scroll | Same `3rem` zone and speed as section 4, on the scroll parent of `#lyricsSections` (not inside the textarea; a textarea taller than the view is reached by the page scroll) |
| Collapsed section | Pointer dwell of 600ms on its header expands it (header tint, section 2.5). Every section auto-expanded by this drag collapses back on release unless it received the word |
| Phone bottom-sheet layout (F7) | At the drag start, if the lyrics sheet is not showing, switch to the 歌詞 tab by `transform` (the AI sheet is moved off-screen, never `display: none`, so pointer capture survives). On cancel, switch back to the previous tab. At ≥ 901 or when both are visible, no switch |
| Touch hint | While a touch drag is active, `.drag-hint` (fixed, top `calc(env(safe-area-inset-top) + var(--sp-2))`, centered, `0.875rem`/700, `rgba(0,0,0,0.72)` pill with white text like the toast, `role="status"`) says 「拖到想放的位置，放開就插入；放在歌詞外面就取消」. Not shown for mouse |
| Cancel | Esc, `pointercancel`, or release outside any textarea |

### 8.2 After the drop

Insert exactly the word at the index (no added space or punctuation, F6). Update the model and save, record one undo step, flash the section (D-14), update counts, announce 「已插入「{詞}」到{段落名}」 (`#lhLive`, word cut to 16). Desktop: focus the textarea with the caret right after the inserted word. Touch: no focus (D-13).

### 8.3 Keyboard alternative

None. The requirement (AI-06) is drag only; the saved-word pool and normal typing remain the keyboard path. Recorded as an accepted accessibility gap, not an oversight.
