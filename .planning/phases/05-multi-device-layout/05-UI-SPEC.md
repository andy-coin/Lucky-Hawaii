# Phase 5 — UI Design Contract（多裝置版面與流暢度）

> Visual and interaction contract for Phase 5. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Andy said "decide yourself, don't ask me" — every open question below was decided by the researcher and is recorded as a **D-xx decision** (section 1). Overriding a D-xx later means editing this file, not the code.
> This phase is **not a redesign**. Colors, fonts, CSS variables, light/dark themes and custom colors are preserved. The job is to make the existing app work on phone / tablet / desktop.
> All UI text is Traditional Chinese (台灣繁體). Simplified Chinese is forbidden.

| ID | Decision | Rationale |

### Existing defects this contract fixes (verified in current code)

1. **Zoom clips edges.** `zoomIn/zoomOut` set `style.zoom` on `.container` (js/search-ui.js:19,25), which has `height: calc(100vh - 40px)` and `max-width: 900px` → at 150% the container is 1.5× the viewport tall and is cut off; panels and modals never scale. The hidden `#zoomSlider` still writes `style.zoom` too (js/theme.js:53-62).
2. **Phone height is wrong.** Body padding is 24px each side but `.container { height: calc(100vh - 20px) }` (css/responsive.css:355) → 28px overflow; `100vh` ignores browser chrome and the keyboard; the fixed tab bar overlays the container bottom.
3. **Device mode frozen at load.** `phone = innerWidth <= 440` (js/cards.js:1) and `innerWidth <= 900` (js/ui-common.js:60, js/init.js:22) are read once; rotation leaves the batch panel, theme label and panels in the wrong state.
4. **Missing features on M and L** — see D-11.
5. **Panels cover controls on L** — see D-03.
6. **Banner covers header controls** — see D-05.
7. **Touch targets far below 44px** (approx.): zoom buttons ~30, mode buttons ~28, `.mark-badge` 18, filter chips ~24, `.rhyme-mode-btn` ~28, `.input-mode-btn` ~22, `.hashtag-add-btn` 22, `.about-btn` 22/18, `.section-remove` ~18, `.panel-add-btn` ~26, lyrics section header ~26, `.chip-remove` ~14, `.batch-btn` ~30, side-panel tab 40 wide, checkbox 18.
8. **Input font < 16px** at 441–900 (`.search-input` clamp → 15.2px at 820) and in all panels/modals at ≤ 900 (`.section-textarea` 15.2px, `.context-textarea` 14px, `.section-label` 12.8px, `.model-select` 11.5px, feedback/hashtag inputs 14–14.4px).
9. **Unsquashable lyrics.** `.lyrics-section { flex: 1 }` divides the sheet height equally, so 5 sections leave ~60px textareas.
10. **Hidden sheets are focusable** (transform-only hiding).
11. **Section delete has no confirmation** (js/lyrics.js:227).
12. **`.m-batch-btn` positioning hacks** (`left:-14px`, `right:-14px`) break at other widths.

## 2. Breakpoints & Device Tiers

| Tier | Viewport (px, unscaled) | Reference device | Layout mode | Side panels | Density |
|------|-------------------------|------------------|-------------|-------------|---------|
| **S** | ≤ 440 | 390×844 phone portrait | Single column; bottom sheets + 3-tab bar | Bottom sheet, full width | Compact (existing S rules) |
| **M** | 441–900 | 820×1180 tablet portrait; 844×390 phone landscape; foldables | Single column; bottom sheets + 3-tab bar | Bottom sheet, width `min(100%, 44rem)`, centered | Desktop type, S gutters |
| **L** | ≥ 901 | 1440×900 desktop; 1180×820 / 1024×768 tablet landscape | Centered container + push side panels with edge tabs | Push panel, width `--panel-w` | Desktop |

Rules:

- Breakpoints live only in media queries and in one JS helper pair in `js/layout.js`: `lhIsSheetMode()` = `matchMedia('(max-width: 900px)')`, `lhIsPhone()` = `matchMedia('(max-width: 440px)')`. Every `window.innerWidth <= 900` / `phone` read is replaced by these helpers, and a `change` listener re-applies state (panel collapse, batch-panel relocation, theme label, tab bar, `inert`) so rotating or resizing works without reload.
- Desktop-only side-panel rules move into `@media (min-width: 901px)` so the sheet rules no longer need `!important` overrides.
- `(pointer: coarse)` is orthogonal: on any width it enables the touch floors (D-07, D-08).
- Functional-only extra viewports (no screenshot baselines): **844×390** (landscape phone) and **1180×820** (tablet landscape).

## 3. Scale System — `--ui-scale`

```
:root            { --ui-scale: 1; }
html             { font-size: calc(100% * var(--ui-scale)); -webkit-text-size-adjust: 100%; }
body             { font-size: 1rem; }
```

- All layout sizes, paddings, gaps, radii, type sizes and panel/sheet dimensions are **rem**. The following stay in px (unscaled): 1–3px borders and outlines, box-shadow offsets/blur, `backdrop-filter` radius, media-query breakpoints, `env()` insets, `--page-pad`, and the touch/input floors (`44px`, `16px`).
- `js/layout.js` (new, loaded in `<head>` right after `safety.js`) owns `setUiScale(pct)`:
  1. clamp to 50–150, round to step 5, invalid / missing stored value → 100;
  2. `document.documentElement.style.setProperty('--ui-scale', pct / 100)`;
  3. update `#MzoomValue` text (`"100%"`);
  4. persist with `lhSet('lh:uiScale', pct)`; register `{ key: 'lh:uiScale', group: 'ui' }` in `LH_KEYS` (safety.js) and update the tests that assert the registry size (currently 16);
  5. set `disabled` + `aria-disabled` on ➖ at 50 and ➕ at 150.
- `zoomIn()` / `zoomOut()` (js/search-ui.js) keep their names (inline `onclick`, smoke test) and delegate to `setUiScale(current ± 5)`. `MzoomScale`/`MzoomBaseRatio` globals and every `style.zoom` write are deleted, including the dead `#zoomSlider`/`.zoom-control` markup, CSS and listeners in js/theme.js.
- Containers must be fluid so scale never clips: `.container { width: 100%; max-width: min(56.25rem, 100%); }`, grids use `auto-fill`, flex rows use `flex-wrap: wrap` (the S rule `.options { flex-wrap: nowrap }` is removed), text in fixed-width chips uses `min-width: 0; overflow-wrap: anywhere`.
- At 100% the app must be visually identical to today (Pass A criterion, section 12).
- Never put `transform`, `filter`, `contain`, `content-visibility`, or `will-change: transform` on `.container` or any ancestor of the fixed overlays (`#settingsOverlay`, `#aboutOverlay` live inside `.container`); they would become containing blocks and clip the overlays.

## 4. Layout Shell

### Viewport and safe area

```html
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover, interactive-widget=resizes-content">
```

`maximum-scale` / `user-scalable=no` are forbidden (pinch-zoom stays available).

```
:root {
  --app-h: 100dvh;                     /* @supports not (height:100dvh) → 100vh */
  --page-pad: 20px;                    /* M: 16px, S: 12px */
  --tabbar-h: max(3.5rem, 48px);       /* only used ≤ 900 */
  --kb-inset: 0px;  --vv-top: 0px;     /* written by js/layout.js while kb-open */
  --tab-w: 2.5rem;                     /* side-panel edge tab; coarse: 2.75rem */
  --panel-w: min(clamp(20rem, 30vw, 25rem), 45vw);
  --hit: max(44px, 2.75rem);
  --pad-t: max(var(--page-pad), env(safe-area-inset-top));
  --pad-b: calc(max(var(--page-pad), env(safe-area-inset-bottom)) + var(--body-extra, 0px));
}
body       { padding: var(--pad-t) max(var(--page-pad), env(safe-area-inset-right)) var(--pad-b) max(var(--page-pad), env(safe-area-inset-left)); min-height: var(--app-h); overscroll-behavior: none; }
.container { height: calc(var(--app-h) - var(--pad-t) - var(--pad-b)); }
@media (max-width: 900px) { body { --body-extra: var(--tabbar-h); } }
html.kb-open body { --body-extra: 0px; }
```

Result: the page itself never scrolls (`documentElement.scrollHeight ≤ innerHeight + 1`); only inner areas scroll. `.results-section { padding-bottom: 100px }` (panels.css:757) is reduced to `1.875rem` on L and `1rem` on ≤ 900 (the body already reserves the tab bar).

### Keyboard / visualViewport (`js/layout.js`)

- Track `stableH` = `max(innerHeight)` since load / last orientation or width change.
- On `visualViewport` `resize` and `scroll` (rAF-throttled) and on `focusin`/`focusout`: `kbOpen = isTextFieldFocused && (stableH − vv.height ≥ 150)`.
- kb-open: `html.classList.add('kb-open')`, `--app-h = vv.height + 'px'`, `--vv-top = vv.offsetTop + 'px'`, `--kb-inset = max(0, innerHeight − vv.height − vv.offsetTop) + 'px'`. kb-closed: remove the class and the three properties (falls back to `100dvh`).
- On `focusin` of a text field inside a scroll container while kb-open: after 250 ms, `el.scrollIntoView({ block: 'nearest' })`; fields get `scroll-margin-bottom: 1rem`.
- Layout response while kb-open (≤ 900):
  - `.mobile-tab-bar { display: none }`, `.copy-toast` anchors to `bottom: calc(var(--kb-inset) + 1rem)`.
  - An open sheet becomes `top: var(--vv-top); bottom: auto; height: var(--app-h); border-radius: 0` (full visible height, input can never sit under the keyboard).
  - Modal overlays (`.settings-overlay`, `.about-overlay`, `.hashtag-popup-overlay`, `.feedback-modal-overlay`) use `top: var(--vv-top); height: var(--app-h); inset-inline: 0` so centered dialogs center in the visible area.
  - When `--app-h < 600px`: `.header` and `.mobile-batch-area` are `display: none` and `.results-section { min-height: 0 }` so results stay visible above the keyboard.
  - In the lyrics sheet, `.side-panel:has(.section-textarea:focus) .context-section { flex-basis: var(--hit); }` collapses 情境&標籤 while writing lyrics.

## 12. Progressive Card Rendering (PERF-02)

Pipeline for `displayResults(results)` (all three modes: common / initial / tone). Count `N` and the header 「找到 N 個字」 are known before rendering (after filters) and shown immediately.

| State | `#resultsContainer[data-render]` | What the user sees | Rules |
|-------|----------------------------------|--------------------|-------|
| Idle | `idle` | Empty-state or 「沒有找到結果」 | No status row |
| **First batch** | `first` (set synchronously at the start of `displayResults`) | Header + first group title + first **48** cards, rendered in one synchronous step | Time from input event to first cards: target ≤ 400 ms at 4× CPU throttle (excluding dictionary/wordlist loading); `aria-busy="true"` on the container |
| **Loading more** | `more` | Cards keep appending; status row 「載入中… 已顯示 n / N 字」 is the last child of `#resultsContainer`, `min-height: var(--hit)`, `0.875rem`, `var(--text-secondary)`, subtle opacity pulse (disabled under reduced motion) | **96** cards per `requestAnimationFrame` slice, stop the slice at **8 ms**; update the status text once per slice; append only below existing content (no insertion above the viewport, so no scroll jump) |
| **Done** | `done` | All cards present, status row removed | `aria-busy` removed; fire `window.dispatchEvent(new Event('lh:render-done'))`; DOM identical to the old one-shot render (golden compares post-`done`) |

Behavior rules:
1. **Order and grouping unchanged.** Groups open (title + empty grid) in order, only when their first card is about to render; groups never reorder; each group's title shows its final count `（k）` from the start.
2. **Cancellation.** A new query, filter change, theme re-render or mode switch increments `_renderEpoch`; the running slice loop checks it and stops; stale cards are never appended.
3. **Scroll.** New query → `.results-section.scrollTop = 0`. Re-render of the **same** query (tier edit via `scheduleReorder`, theme/color change, filter checkbox) keeps position: render synchronously until the content covers `previousScrollTop + 2 × clientHeight` (or all if N ≤ 300), restore `scrollTop`, then continue progressively.
4. **Interaction while rendering.** Card taps, badge taps, selection and batch marking work on already-rendered cards; selection state survives appended batches.
5. **No new libraries.** Optional `content-visibility: auto; contain-intrinsic-size: auto 12rem` on `.group-section` (never on `.char-card`, never on `.container` — see section 3); `.char-card { transition: transform .2s ease, box-shadow .2s ease, border-color .2s ease }` replaces `transition: all`.
6. **Test signal.** `tests/helpers.mjs` gets `waitRenderSettled(page)` = wait until `#resultsContainer[data-render]` is `done` or `idle`. Golden tests use it.
7. **Throttle targets (starting values, confirmed in Wave 0).** Chromium CDP `Emulation.setCPUThrottlingRate`: at **4×** no `longtask` entry > **150 ms** and total blocking time (Σ max(0, duration − 50)) ≤ **300 ms** during the largest golden query; at **6×** no entry > **250 ms**. Wave 0 records the current worst long task; the new value must also be ≥ **3× better** than that recorded value. Measure median of 3 runs.
