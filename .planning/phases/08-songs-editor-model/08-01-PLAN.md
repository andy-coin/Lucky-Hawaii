## Phase Goal

ROADMAP Goal (kept verbatim; it is not in user-story form, which was surfaced to the orchestrator instead of inventing a story): 歌詞改以資料模型為準，打字（含注音組字）不再被打斷；可以像 Google Docs 一樣用側邊分頁管理多首歌，並匯出、備份、換裝置還原。

<objective>
Tracer for the riskiest layer first: the first real schema migration (1→2) inside the existing safety layer. A v0.96 user who opens the new version gets two safety backups, then a new-format copy of their song (lh:songs, 「我的第一首歌」, byte for byte) while the old keys stay untouched; crashes, a second tab, corrupt data, failed writes and a full disk all end in a safe state.

Purpose: the migration half of EDIT-04 and the data-safety constraint, proven in isolation on the storage layer before any editor code depends on it. The editor switches to lh:songs in 08-02 (next wave); until then it keeps its v0.96 behaviour, and nothing ships between the two plans (branch-local, executors never push).
Output: migration step and registry in js/safety.js, ?v=0.96.12, songs-migrate specs (RED first), storage / scan specs on schema 2.

Decisions implemented: A1 (keys), A2, A3 (rollback / blocked paths), F3, F9.
Reversibility (recorded, no gate per REVERSIBILITY_GATES=false): the schema migration is rated costly — reversible because legacy keys are never written by the step and 'pre-schema-2' is stored first, but every later phase builds on lh:songs.
</objective>
