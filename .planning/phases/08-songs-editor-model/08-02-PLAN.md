## Phase Goal

ROADMAP Goal (kept verbatim; it is not in user-story form, which was surfaced to the orchestrator instead of inventing a story): 歌詞改以資料模型為準，打字（含注音組字）不再被打斷；可以像 Google Docs 一樣用側邊分頁管理多首歌，並匯出、備份、換裝置還原。

<objective>
Switch the editor onto the model that 08-01 created. The path runs through model (new js/songs.js, js/state.js shells) → boot order (wait for window.__hoyunSafetyReady, A3) → editor (js/lyrics.js renders the active song with DOM APIs and writes keystrokes only into memory) → consumers (AI reads the model) → persistence (300 ms debounced merge-write to lh:songs; legacy single-song mode when the migration did not run).

After this plan, a v0.96 user who upgrades sees the old lyrics as 「我的第一首歌」 and can keep typing, including Zhuyin composition. Every word is saved to the new format and nothing writes the old keys.

Purpose: EDIT-01 core (the model is the source of truth) and the visible half of the EDIT-04 migration. Cross-tab sync, the song list, export and backup all build on this.
Output: js/songs.js, a DOM-API editor, RED-first specs (songs-ime R1, songs-model R2/R3) and the existing suites moved onto the model.

Decisions implemented: A1, A3, A4, B1, B2, B3 (sections, labels and #tags here; saved words in 08-03), B4, C6, F2, F10 (js/songs.js).
</objective>
