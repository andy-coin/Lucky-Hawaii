# Phase 8 — UI Design Contract（歌曲管理與資料模型）

> Visual and interaction contract for Phase 8. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Andy pre-authorized "decide grey areas yourself". Every choice below that 08-CONTEXT.md did not lock is tagged **(Claude's discretion)** and is listed in section 1 as a **D-xx** so Andy can veto it later by editing this file.
> This phase is **not a redesign**. It adds one list, two menus/dialogs and a print sheet around the existing lyrics panel. The section modules (`.lyrics-section`, `.section-label`, `.section-textarea`, `.section-remove`, collapse chevron), the 情境 & 標籤 block and the hashtag chips **keep their look unchanged** (Phase 9 redesigns them). Typing must not re-render any textarea; that is a data-flow rule (CONTEXT B1), not a visual one, and is restated in section 9 only where it affects what the user sees.
> Reuses Phase 5 (rem, `--hit` 44px, `--sp-*`, breakpoints S ≤ 440 / M 441–900 / L ≥ 901, z-index scale, light / dark / custom themes, `html.kb-open`) and Phase 7 (`--action-*` tokens, `.feedback-modal-overlay` dialog shell, report-tile pattern, specific verb+object labels, no generic 「取消」, multiples of 4px, AA contrast decided up front, no new hex literals in layout rules).
> All UI text is Traditional Chinese (台灣繁體). Simplified Chinese is forbidden.

## 1. Decisions Log

| ID | Decision | Rationale |
|----|----------|-----------|
| D-01 | **Header layout.** The old `.side-panel-title` row (`📝 歌詞` + `+ 新增段落`) becomes one wrapping flex row `.lyrics-head` with DOM order: `[☰ 歌曲]` · current song title `.song-current` (`flex: 1 1 8rem; min-width: 0`, ellipsis) · `[⬇ 匯出]` · `[+ 新增段落]` (the latter `margin-inline-start: auto`). At 390px the first three fit one line and `+ 新增段落` wraps to its own right-aligned line; at 704px (M sheet) and on L inner width ≈ 335px it also fits or wraps naturally. The `📝 歌詞` caption is dropped (the song title replaces it); the edge tab on L still reads 「歌詞」. (Claude's discretion) | One wrapping row survives scale 150% and short landscape phones without a second layout. The title is the most important text on the row and gets the flexible slot. |
| D-02 | **List placement, L ≥ 1024 (push column).** The list is an in-flow column inside the left panel, to the left of the lyrics area and below `.lyrics-head`, width `--song-w: 9rem` (144px). While the list is open the left panel is widened by exactly `--song-w` (`.left-panel { width: calc(var(--panel-w) + var(--song-w, 0px)) }`, `body.lp-open { padding-left: calc(var(--panel-w) + var(--song-w, 0px) + var(--page-pad)) }`, `body.songs-open { --song-w: 9rem }`), so the lyrics area keeps today's width and the container re-centers (Phase 5 D-03). No width transition (same reason as Phase 5: avoids per-frame reflow); the list appears instantly. The Phase 5 both-panels-open check (container ≥ 24rem) must count `--song-w`; if it fails, the right panel collapses as today. **Overrides CONTEXT C1 (「左側滑出一欄」): the column appears instantly instead of sliding — for Andy to veto.** (Claude's discretion) | Matches "Google Docs 側邊分頁" and CONTEXT C1 「左側滑出一欄」 without squeezing the lyrics. "Slide" is satisfied by the column appearing at the left edge; animating width is deliberately skipped. |
| D-03 | **List placement, ≤ 1023 (overlay).** Phone / tablet portrait (the 歌詞 sheet) **and** 901–1023 wide L panels use an overlay: `.song-list` is `position: absolute; inset: 0` inside `.lyrics-layout` (the area under `.lyrics-head`), covering the lyrics area and the 情境 & 標籤 block, never the `.lyrics-head` (so ☰ 歌曲 stays reachable). It expands with `opacity 0 → 1` and `translateY(-0.5rem) → 0` over 0.2s ease. `prefers-reduced-motion`: no animation. Width is 100% of the panel body, so ✎ and 🗑 fit inline. (Claude's discretion) | CONTEXT C1 「手機由上方展開覆蓋」. 901–1023 has no room for +144px (container would drop below 24rem), so it reuses the sheet behavior instead of adding a third layout. |
| D-04 | **Open state persistence** (refines CONTEXT C1's `lh:songListOpen`: the key still exists and is registered, it is just not used in overlay mode). `lh:songListOpen` is read and written **only in push-column mode (≥ 1024)**. In overlay mode the list always starts closed on load and its toggling writes nothing. (Claude's discretion) | A phone must not reopen on top of the lyrics at every launch, and a phone toggle must not overwrite the desktop preference. |
| D-05 | **Selecting a song.** Tapping a song name switches to it immediately (the previous song is flushed first, CONTEXT B2). In overlay mode the list then closes and focus moves to ☰ 歌曲; in push-column mode the list stays open so Andy can flip through songs. No toast. | Overlay hides the lyrics, so the user needs to see the result; the column does not. |
| D-06 | **Row actions.** Overlay mode (wide rows): every row shows `[name][✎][🗑]` inline. Push-column mode (144px): only the **active** row shows ✎ 🗑, in a second line under the name. Double-click on a name starts rename in push-column mode only; ✎ is the canonical path everywhere (a double-click in overlay mode cannot land because the first click closes the list). **Overrides CONTEXT C3 (「點 ✎ 或雙擊歌名進入編輯」): double-click rename is only available in push-column mode; ✎ works everywhere — for Andy to veto.** (Claude's discretion) | 144px cannot hold a name and two 28–44px buttons; hiding actions for non-active rows keeps the column readable. |
| D-07 | **＋ 新增歌曲 flow.** Creates 「未命名歌曲 N」 at the top, switches to it, keeps the list open and puts the new row into rename (input focused, text selected). After Enter / blur commit: overlay mode closes the list (no auto-focus into a textarea, so the phone keyboard does not pop up); push-column mode leaves it open. Esc during this first rename keeps 「未命名歌曲 N」. | CONTEXT C2, plus an explicit hand-off so the keyboard and list never fight. |
| D-08 | **Delete uses a real dialog, not `confirm()`.** Reuses the `.feedback-modal-overlay` shell as `role="alertdialog"` with specific buttons 「先不刪除」 / 「刪除這首歌」, default focus on 「先不刪除」. | CONTEXT C4 says "既有對話框樣式"; native `confirm()` offers only generic OK/Cancel and cannot hold the extra last-song sentence. Phase 5's `confirm()` for sections stays unchanged (Phase 9 replaces it with Undo). |
| D-09 | **New danger tokens.** `:root { --danger-bg: #c53030; --danger-bg-hover: #9b2c2c; --danger-text: #fff; --danger-line: #9b2c2c; }` and under `[data-theme="dark"]` only `--danger-line: #fc8181`. Defined once in `css/base.css` next to `--action-*`; the custom-color picker / `loadColors()` do not touch them. White on `#c53030` ≈ 5.5:1 (filled buttons). For **text and outlines**, `--danger-line` is `#9b2c2c` in light (≈ 6.0:1 on `--container-bg` `#eee3ce`, ≈ 7.2:1 on `--card-bg` `#f7fafc`) and `#fc8181` in dark (≈4.9:1 on `#2d3748`, higher on the default dark container). Replaces the failure-only `#e53e3e` (≈ 4.0:1 with white) for filled destructive buttons. (Claude's discretion) | AA decided up front; keeps rule "no new hex literals in layout rules" because rules reference variables only. |
| D-10 | **Export menu** is a small popover (`#exportMenu`, built on `.word-ctx-menu` + `.word-ctx-item`), opened by ⬇ 匯出, placed with `lhPlaceMenu`, flips above the button when there is no room, closes on outside tap, Esc, or choosing an item. Each item has a label (0.875rem/700) and a one-line hint (0.75rem/400). Order: TXT（預設）· Markdown · PDF（列印）· divider · 複製整首. | CONTEXT D1. Hints make the PDF steps and the file type visible before the click. |
| D-11 | **Blank sections are skipped in all four outputs** (TXT, Markdown, PDF, copy); a blank label falls back to 「段落 {n}」 (n = 1-based position among exported sections). A song whose every section is blank is not exported: toast 「這首歌還沒有歌詞可以匯出」. (Claude's discretion) | Empty 「[Verse]」 headers are noise in a lyric sheet; nothing is lost because blank sections contain nothing. |
| D-12 | **PDF = hidden print sheet + `window.print()`.** JS fills `#printSheet` (hidden on screen) with `textContent`, calls `window.print()`, clears it on `afterprint`. The print rules live in a new `css/print.css` linked with `media="print"` (add the shared `?v=` like every other css file). In print, every `body > *:not(#printSheet)` is `display: none`. | Zero dependencies, no layout leakage from panels, works the same on iOS (share / save to Files). |
| D-13 | **Backup buttons.** Header `SAVE` / `LOAD` become 「備份全部」 / 「匯入備份」 (icons 💾 / 📂 kept, `.save-load-text` carries the words, short on desktop). The same two buttons in the settings dialog (the only place on ≤ 900, Phase 5 D-11) become 「💾 備份全部」 / 「📂 匯入備份」. `title` and `aria-label` spell out the full action (section 8.1). | CONTEXT E2. |
| D-14 | **Import dialog default is the safe choice.** Two stacked tiles; **「只加入歌曲」 comes first** (filled `--action-bg`, never destroys anything), 「全部還原（取代目前資料）」 second (danger outline, ⚠ glyph, hint states the automatic backup). One step, no second confirm: the label already says "取代", the hint says the current data is backed up first, and the result toast says so. A v1 file shows only one tile, 「加入成新歌曲」. (Claude's discretion) | The order and styling make the irreversible-feeling option the deliberate one. A double confirm would add friction for the legitimate "new device" restore. |
| D-15 | **Errors are a dialog state, not a toast.** Bad-file messages are 1–3 sentences; the toast (nowrap pill) is too small. The import dialog switches to an error view (title 「這個檔案無法匯入」, one paragraph, one button 「關閉錯誤訊息」). Every message ends with 「目前的歌詞與設定都沒有被改動。」 (CONTEXT E5). | White-language errors need room; the sentence about no changes reassures a data-anxious user. |
| D-16 | **Toast fix.** `.copy-toast` currently has `white-space: nowrap`, so a toast longer than the viewport is clipped. Change to `white-space: normal; max-width: min(92vw, 28rem); text-align: center; line-height: 1.5`. Song names inside toast copy are cut to 16 characters + 「…」. Durations: copied 1800 (default), exported / backed up / blocked 2400, other-tab reload / migrated / import result 4000. | New toast copy includes user-chosen names (up to 60 chars). |
| D-17 | **Typing never shows UI.** There is no "saving…" indicator, no spinner, and no re-render flicker (300ms debounce, flush on blur / compositionend / switch / pagehide). The only autosave feedback is the existing `#lhSaveBanner` on failure. | Andy cares most about 注音 composition feel; any visible churn is a regression. |
| D-18 | **Order and naming of the list.** Sorted by `createdAt` descending (CONTEXT C5). Duplicate names are allowed in the UI (the importer adds 「（匯入）」 for add-only imports). Names are max 60 characters (`maxlength="60"`), trimmed; an empty or whitespace-only result reverts to the previous name silently. | CONTEXT C3 / C5. |
| D-19 | **Weights / sizes.** Every new or changed screen rule uses only 4 sizes (0.75 / 0.875 / 1 / 1.25 rem) and 2 weights (400 / 700), including the header 備份全部 / 匯入備份 buttons (0.875rem/700, replacing legacy 0.8rem). The print sheet's 20 / 14 / 12 pt scale is a **separate medium** (`@media print`, `css/print.css`) and is not counted against the screen limit. |
| D-20 | **Which fill is the primary.** Two rules, no overlap: (a) *create-in-place* buttons on the working surface (＋ 新增歌曲, + 新增段落) use the existing accent fill `--highlight-border` via `.panel-add-btn`; (b) the *primary choice inside a dialog* (只加入歌曲, and Phase 7's 送出回報) uses `--action-bg`; a destructive dialog primary (刪除這首歌) uses `--danger-bg`. Different surfaces, one fill per role. (Claude's discretion) | Avoids two competing accent fills inside one dialog while keeping the existing panel button look. |
| D-21 | **Focal points.** Lyrics screen: the lyrics text area (largest block; `.song-current` is the only 1rem/700 text above it, so the eye goes title then text). Song list: the active row (`--container-bg` fill, accent stripe, bold name), the only filled row. Import dialog: the 「只加入歌曲」 tile, the only filled control (the 全部還原 tile is outline only). (Claude's discretion) | One focal point per surface. | Phase 5 D-13 / Phase 7 D-17. |

### 4.2 File and clipboard content (visible contract)

**TXT** (UTF-8, no BOM, `\n`): first line the song title, one blank line, then for each non-blank section a line 「[段落名]」 followed by its text, one blank line between sections, single trailing newline.

```
{歌名}

[{段落名}]
{第一句}
{第二句}

[{段落名}]
…
```

**Markdown**: `# {歌名}`, blank line, then per section `## {段落名}`, blank line, each lyric line followed by two spaces before the line break (hard breaks), blank line between sections. A lyric line that begins with `#`, `>`, `-`, `*`, `+` or a digit followed by `.` is escaped with a leading backslash so it cannot turn into markup.

**Copy** = the TXT string. `navigator.clipboard.writeText` first; on rejection the legacy select-and-`execCommand('copy')` path; if both fail the toast is 「複製失敗，請改用「TXT」下載」.

**File names**: `{歌名}.txt` / `{歌名}.md`; characters `\ / : * ? " < > |` and control characters become `_`; trimmed; fallback 「未命名歌曲」.

### 4.3 Print sheet (PDF)

`#printSheet` is a direct child of `<body>`, `display: none` on screen (also `aria-hidden="true"`), filled just before `window.print()` and emptied on `afterprint`. All text via `textContent`.

```
#printSheet
  h1.print-title            {歌名}
  section.print-section ×N  (non-blank sections only)
     h2.print-label         {段落名}
     p.print-text           {歌詞，white-space: pre-wrap}
```

`css/print.css` (linked `media="print"`):

| Rule | Value |
|------|-------|
| Page | `@page { size: A4; margin: 20mm 16mm; }` |
| Visibility | `body > *:not(#printSheet) { display: none !important; }` `#printSheet { display: block !important; }`; no buttons, panels, tab bar, toast, header or footer chrome; no URL / date / page-number text added by the page |
| Colors | `html, body { background: #fff !important; color: #000 !important; }` — the **only** place hex literals are allowed in this phase besides the token definitions; backgrounds, shadows and borders are removed everywhere in the sheet; `-webkit-print-color-adjust: exact` is not needed |
| Title `h1` | `20pt` / 700 / 1.2, `margin: 0 0 16pt`, text-align left |
| Section label `h2` | `12pt` / 700 / 1.5, `margin: 16pt 0 4pt`, `break-after: avoid` |
| Lyrics `p` | `14pt` / 400 / 1.8, `margin: 0`, `white-space: pre-wrap; overflow-wrap: anywhere` |
| Section | `break-inside: avoid` when the section has ≤ 12 lines (sections longer than a page may split); `margin-bottom: 8pt` |
| Font | `'Noto Sans TC', sans-serif` |

Spacing in print uses multiples of 4pt; sizes are a separate 3-step scale (20 / 14 / 12 pt).
