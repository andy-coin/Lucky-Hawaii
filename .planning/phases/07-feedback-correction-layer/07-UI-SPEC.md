# Phase 7 — UI Design Contract（回報與修正層）

> Visual and interaction contract for Phase 7. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Andy pre-authorized "decide grey areas yourself". Every choice below that 07-CONTEXT.md did not lock is tagged **(Claude's discretion)** and is listed in section 1 as a **D-xx** so Andy can veto it later by editing this file.
> **Two surfaces, two design systems.** (1) The main site (`index.html`, `css/*.css`, `js/report.js`) reuses the Phase 5 system: rem sizing, `--hit` 44×44 touch floor, CSS variables for light / dark / custom colors. (2) The admin page (`admin/index.html`) keeps **its own** look (its own `:root` variables, px spacing, `.card` / `.btn` / `.topbar` classes). Do not port main-site tokens into admin or the reverse.
> All UI text is Traditional Chinese (台灣繁體). Simplified Chinese is forbidden. This phase is **not a redesign**: no new fonts, no new color families, no new dependencies.

| Block | Spec |
|-------|------|

| Word chips `.report-words` | Flex-wrap, gap `var(--sp-2)`, `margin-bottom: var(--sp-4)`. ### 3.3 Interaction

| Step | Behavior |
|------|----------|
| Open | `openReportDialog(items?)` — items default to the current selection (`.char-card.selected` for the toolbar, report-selected AI cards for report mode, or the single item from the context menu). No selection → toast (D-02), dialog not opened. Reason is **unselected**, note empty. Focus moves to the title (`tabindex="-1"`), **not** the textarea, so the phone keyboard does not pop up. |
| Choose reason | Updates `aria-checked`, note placeholder, the 「已回報過」 chips and the send button state (3.4). Arrow keys move the choice (roving `tabindex`), Space/Enter selects. |
| Send | Button text becomes 「送出中…」 and is `disabled`; reasons and note become `disabled`; 先不回報 stays enabled. Items are posted sequentially with the existing `postFeedback()`; each item is one record (word-level, so admin can group), same `ts`-free payload shape as today plus the fields in D-07. |
| Success (all) | Dialog closes **only after** every post succeeded. Toast: 1 item → 「已回報「{詞}」— {原因}」 (existing wording); n items → 「已回報 {n} 個字詞，謝謝你」. Each sent item is added to the session Set (D-08). AI report mode exits. Char selection is left as is. |
| Esc / 先不回報 | Closes without sending. Overlay click closes only if the note is empty (do not lose typed text). |
| Focus return | On close, focus returns to the control that opened it. |
| Keyboard open | Inherits `html.kb-open .feedback-modal-overlay` rules (centers in visible area, `max-height: calc(var(--app-h) - 2rem)`, internal scroll). Note focus uses `scroll-margin-bottom: 1rem`. |

### 3.4 States

| State | What the user sees |
|-------|--------------------|
| No reason chosen | 送出回報 `disabled` (`opacity: .5`); status line empty. |
| Reason chosen, none reported before | 送出回報 enabled, label 「送出回報」 (n ≥ 2: 「送出回報（{n} 個）」). |
| Some already reported (same reason) | Those chips show 「已回報過」; status line 「{k} 個已回報過，會略過」; label counts only the new ones, e.g. 「送出回報（{n−k} 個）」. |
| All already reported (same reason) | 送出回報 `disabled`; status line 「這些字詞已經用這個原因回報過了」. |
| Over 10 items | Only the first 10 are kept; status line 「一次最多回報 10 個，已先取前 10 個」. |
| Sending | As in 3.3; status line 「送出中…」. |
| Failure, nothing sent | Dialog stays open, note and reason kept; the existing toast 「回報沒有送出，請檢查網路後再試一次」 shows, and the status line repeats it in destructive color; 送出回報 re-enabled so the user can retry. |
| Failure after some sent (multi) | Sent ones are added to the Set and show 「已回報過」; status line 「已送出 {k} 個，還有 {m} 個沒送出，請再按一次送出」; dialog stays open. |
| Rate limited (HTTP 429) | Treated as failure-after-k with the status line 「回報得太快了，請過一分鐘再試」; the generic toast is replaced by this text. `postFeedback()` must expose the status (planner: return `{ok, status}` or throw a typed result; the existing `true/false` callers keep working). |
| Stale content | Dialog uses a snapshot of the items taken at open; selection changes behind the overlay do not alter it. |

### 3.5 Accessibility and theming

- `role="dialog" aria-modal="true"`, Tab cycles within the dialog (overlay covers the page; simple focus trap on the 5–8 controls), `Esc` closes.
- Reason buttons are a `radiogroup`; chosen state is exposed via `aria-checked`, not just color.
- `:focus-visible` ring from Phase 5 (2px `var(--highlight-border)`) applies; do not set `outline: none` without a replacement.
- `prefers-reduced-motion`: the dialog has no animation; nothing to disable.
