## Phase Goal

**As a** 開發者兼作詞人 Andy, **I want to** 一個指令就跑完查韻回歸測試、讓所有錯誤看得見、資料改格式前自動備份, **so that** 之後每一步改動（AI 搶修、拆檔）都能立刻知道有沒有弄壞東西，歌詞與設定一個都不少。

<objective>
Give user data a real backup before anything ever changes its format. Upgrade the app's IndexedDB to version 2 through one shared opener (keeping the wordlist cache, never hanging on a stale tab), make wordlist-cache write failures visible as a gentle toast, then store a baseline backup of every registered key at first open, keep the newest 3 backups, and make backup failures visible with a fallback copy in localStorage.

Purpose: FND-03 (backup before format change, keep-3, baseline) and PERF-04 (IndexedDB write failures are visible). Plan 06 builds the migration runner and restore on top of `lhBackup` / `lhListBackups`.
Output: IndexedDB opener, backup layer and boot sequence in js/safety.js; `_idbOpen` / `_idbPut` changes in index.html; storage.spec and save-failure.spec tests.

Decision IDs (planner-assigned to CONTEXT.md decision bullets in document order):
- D-07 background errors → console only with 「[好韻器]」
- D-09 save-failure banner: sticky, dismissible, advice, throttled
- D-11 backups live in a separate IndexedDB object store (not the wordlist cache `wl`), newest 3 kept; when IndexedDB is unavailable, fall back to one backup copy in localStorage and log a warning
- D-12 back up before every format upgrade; on first open of the new version store a baseline backup
- D-13 one registry of known keys shared by backup and tests; never back up the whole origin
Orchestrator decision O-2 (locked): wordlist-cache write failure → one-time non-sticky toast + 「[好韻器]」 record; backup-store write failure → sticky banner. Both tested automatically. O-6 never git push.
Edge refinement (recorded): the orchestrator-proposed edge "IndexedDB backup failure while localStorage works still surfaces the banner" is kept for write failures (O-2); a wholly unavailable IndexedDB follows D-11 literally (fallback + warning, no banner) unless the fallback also fails.
</objective>
