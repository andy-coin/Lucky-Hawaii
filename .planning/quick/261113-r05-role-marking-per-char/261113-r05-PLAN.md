Design choices (smallest model that survives edits):
- Data. `song.roles = [{ id, name, color }]` holds at most 8 roles. Ids come from `lhNewId('role-')` and are never reused. `section.marks = [{ a, b, r }]` uses UTF-16 offsets, the same units as textarea selectionStart. Ranges are half-open `[a, b)`, sorted, non-overlapping, and touching same-role ranges are merged. Both fields are left out when empty, the same pattern as `cols`/`readings`/`structs`. Old songs, old backups and golden fixtures therefore stay byte-identical. No new storage key is added, so `LH_KEYS` stays at 26 and tests/scan.spec.mjs is untouched (L8).
- Immutability. Undo snapshots are shallow copies (`{ ...s }`), so a `marks` array is never mutated in place. Every change assigns a new array through `lhSecSetMarks`.
- Shift rule (L2), pure function `lhMarksShift(marks, oldText, newText, caret)`. A textarea edit is always one contiguous splice: old `[s, oe)` becomes new `[s, ne)`, with `d = newLen − oldLen` and `oe = ne − d`. A plain string diff cannot place `s` when the typed character equals a neighbour (「愛愛」→「愛愛愛」 fits an insert at 0, 1 or 2), so the caller supplies `caret` = the position right after the new text of the edit. For a textarea that is `el.selectionEnd` read inside the `input`/`compositionend` handler (after insert, paste, IME update: end of the inserted text; after delete: the deletion point). Programmatic writers pass it explicitly.
  - Common prefix `p`, stepped back by one when `old[p-1]` is a high surrogate.
  - Caret path, used when `caret` is an integer with `0 ≤ caret ≤ newLen`, `0 ≤ caret − d ≤ oldLen`, the caret does not split a surrogate pair in newText, and `old.slice(caret − d) === new.slice(caret)`: `ne = caret`, `oe = caret − d`, `s = min(p, oe, ne)`. For a pure insert this pins `s = oe` exactly; for a pure delete it pins `s = ne` exactly. Only a replace of selected text whose new text starts with the same characters as the old is resolved to the smallest change (the identical leading characters keep their marks).
  - Fallback path (no caret, or the caret fails the check): common suffix `q` capped at `min(oldLen, newLen) − p`, stepped back by one when `new[newLen − q]` is a low surrogate; `oe = oldLen − q`, `ne = newLen − q`, `s = p`.
  - Each mark, checked in this order: `b <= s` → keep. `a >= oe` → shift both ends by d. `a <= s && b >= oe` (the mark contains the whole changed region) → `[a, b + d)`, the new text inherits the role. Otherwise → `[a < s ? a : ne, b > oe ? b + d : s)`. Drop the mark if it becomes empty, then normalise.
  - Consequences: typing at a mark's start or end boundary never extends the mark; typing strictly inside it grows it; typing over a whole marked word keeps the role; replacing a range that spans two marks leaves the new text unmarked; select-all plus paste over several marks clears them. The rule was simulated against every unit case in Task 1 (scratchpad sim/shift2.mjs) before this revision.
- Undo (L2). `_sig` includes `s.marks`. Role assignment goes through `lhSecApply`, which adds one undo step. Typing already snapshots the shifted marks via `lhHistTyping`. Creating a role is a song-level setting outside the undo history, the same as song title and section height.
- Display (L3). The textarea stays on top with visible text. The existing mirror underneath (`.rhyme-mirror`, transparent text) wraps marked characters in `span.rl[data-rl=k]`. That span gets a soft wash of the role colour, `color-mix(var(--rl-c) var(--rl-mix), transparent)`. Rhyme blocks are opaque mixes with `--card-bg`, so they sit on top of the wash and the two never fight. Colours go on `document.documentElement` as `--rl0..--rl7`, set in the new js/roles.js. They must not be set in rhyme-map.js, because tests/line-audit.spec.mjs only allows `setProperty` in four rhyme-map.js functions. Changing a colour is therefore instant and needs no repaint.
- UI code lives in one new file, js/roles.js, loaded right after js/rhyme-map.js. This keeps js/sections.js (1265 lines) and js/rhyme-map.js (1840 lines) from growing further, and Part B adds the role panel to the same file.
