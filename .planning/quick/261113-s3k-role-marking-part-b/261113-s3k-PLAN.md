Design choices and deviations from the Part B spec (planner discretion, none touches a locked item):
- Print colour plumbing: print spans carry `data-rl = role index` and reuse the existing global `[data-rl="k"] { --rl-c: var(--rlk) }` rules in css/panels.css (panels.css has no media attribute, so the rules also apply when printing). The `--rl0..--rl7` values are already on documentElement for curSong (lhRolesRefresh), and exportSongAs only ever prints curSong. So song-io.js never handles a colour string and needs no colour validation of its own.
- Print darkening is 60% role colour + 40% black, not the 80% in the spec. 80% gives contrast 3.64 on white for the default yellow; 60% gives at least 5.88 for all 8 defaults (computed before planning). The test locks this.
- Leading whitespace of a marked run goes before the tag (a mark that starts with "\n" exports as 「…\n[女]你愛我」, not 「…[女]\n你愛我」). lhMarksParts splits it into the preceding unmarked part, so both TXT and print get it right with no special case downstream.
- Sections that still have legacy `cols` export exactly as today (【角色】 merge, no [name] tags). Those columns already label roles, and tagging the first column too would print 「【男】[男]…」.
- The spec's 「＋ 新角色 in #roleSelMenu also opens the panel」 is replaced by a toast 「已新增「角色 n」，可按工具列「角色 ▾」改名、改色」. The panel is anchored to the toolbar button, which on a phone is often off-screen while the keyboard is up. An open panel also blocks the selection bar (lhRoleBusy), so auto-opening would get in the way of the next mark.
- The spec's 「lhRolesRefresh refills the panel when open」 is dropped. Every path that calls lhRolesRefresh while the panel could be open goes through renderLyricsSections → lhSecAbortInteractions → lhMapCloseAll, and lhMapCloseAll now closes the panel. The panel refills itself on open, add and delete.
- Role add, rename, recolour and delete stay outside the undo history (known Part A limit, kept by the user's instruction). Delete re-snaps the history baseline so later undo steps don't bring back the deleted role's marks. Older steps from before the delete can still restore them, but they are invisible (unknown role ids aren't painted or exported) and lhSongRolesFix drops them on the next load. This gets a `ponytail:` comment.
